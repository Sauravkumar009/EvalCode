Limits of this report:
1. Tests cannot prove correctness
   Example: A submission passes all 10 hidden tests but fails when the input has extra whitespace or a trailing newline that no test covers. The agent still reports 10/10.
   Fix:     The agent should create its own extra tricky test inputs and compare the student's answers with the answers of a correct program.
2. Empirical complexity estimation is sensitive to OS scheduler noise
   Example: Under heavy background CPU load, an O(1) submission may exhibit variable execution times across sizes, risking false classification as non-constant time.
   Fix:     Combine empirical wall-clock timing with static AST loop/recursion analysis and instruction-count profiling.
